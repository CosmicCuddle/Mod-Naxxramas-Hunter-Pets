# Original 1.12 DBC vs deployed 3.3.5 verification protocol

**Status: READ-ONLY RESEARCH PLAN.** Not executed. No client/server/SQL changes, no core patches, no player data reads. This is the required evidence gate for every proposed Hunter pet spell.

## Scope and immutable version definitions

Research three **different** datasets and do not conflate them:

| Source version | Purpose | Current access/status |
|---|---|---|
| **Original WoW 1.12.1, build 5875** | Original DBC spell/skill/family/rank evidence | **Not available to this research turn**; genuine files need an identified lawful source |
| **CMaNGOS Classic archived spell chain** | Factual historical **candidate** spell IDs/rank predecessor relationships | [Archived chain file](https://github.com/cmangos/mangos-classic/blob/master/sql/archive/0.7/4096_pet.sql) **read and indexed**; includes BC-era ranks |
| **AzerothCore 3.3.5a, expected client build 12340** | Actual compatibility: native pet learned spells, client-visible IDs/effects, trainer and stable logic | **Exact deployed revision and DBC not accessible**; public upstream `spell_ranks.sql` only selectively reviewed |

For original data, source **legitimately obtained original 1.12 client assets**, not private/multiplayer player data, pirate downloads, an unlabeled random fork or a modified Turtle WoW file incorrectly called 'retail 1.12'. Do not commit Blizzard client DBC/MPQ binaries to the public Naxx Hunter Pets repository.

The original game's `Spell.dbc` contains spell data; `SkillLineAbility.dbc` relates skills/ranks; `CreatureFamily.dbc` controls family metadata. Historical trainer **NPC offerings** may be held in emulator DB rather than in client DBC, so a spell in DBC does **not** alone prove it could be purchased. Likewise the 3.3.5 Core's `spell_ranks` SQL table is not the entire Spell.dbc.

## Phase A — prepare immutable read-only copies, no deployment

1. Inventory owner-approved **staging/reference** copy of original 1.12 and current 3.3.5 client data, if available. Record origin, build number and source patch/version; preserve original game files unchanged.
2. Read-only export `Spell.dbc`, `SkillLineAbility.dbc`, `CreatureFamily.dbc` and optionally `PetSpellData.dbc` for **both** systems; any unavailable files/columns are marked missing instead of guessed. Read actual schemas from versioned definitions, because 1.12 and 3.3.5 column layouts differ.
3. Compute **SHA-256 hashes** for **copies** and note tool/repo revision and extraction options; hashes and structured findings only go to GitHub, **not the copyrighted game files**.
4. Before inspecting client assets, preserve the working server `dbc` directory and client patch/config inventory as part of the future backup plan. This is research, **not permission to replace any server/client file**.
5. Keep SQL reads separate from game spell files. A source spell's numeric ID and a world DB trainer wrapper can be two different spells.

Useful **example** for a future Windows/Linux research environment after installing a compatible reader and having lawful original assets:

```bash
# READ-ONLY INPUT: copies of original 1.12.1 DBC files.
# Paths below are illustrative, not the user's real server.
sha256sum Spell.dbc SkillLineAbility.dbc CreatureFamily.dbc
vanilladbc convert Spell.dbc Spell.dbd 1.12.1.5875 --plugin csv --output original-spell.csv
vanilladbc convert SkillLineAbility.dbc SkillLineAbility.dbd 1.12.1.5875 --plugin csv --output original-skills.csv
```

**Reader reference:** [vanilladbc-cli](https://github.com/suprsokr/vanilladbc-cli), [vanilladbc-csv plugin](https://github.com/suprsokr/vanilladbc-csv). The syntax above is example usage, not a command tested in this conversation. Never direct this tool to write into live server files. For 3.3.5 inspect version-correct extraction/DBD tools separately.

## Phase B — prove original 1.12 rank *existence*

Start from [111-row candidate catalogue](../data/reference/vanilla-ability-ranks.csv), [59 wild spell IDs](../data/reference/vanilla-wild-spell-id-candidates.csv), and [52 trainer spell IDs](../data/reference/vanilla-trainer-spell-id-candidates.csv).

For each row:
- Verify `name`, `rank`, unique spell ID, original spell effect(s), resource, icon, description, school, range, mechanic, cast time, cooldown and whether the effect is passive.
- Verify SkillLineAbility row and rank predecessor/next-rank spell. Spell ID collisions, rank-chain gaps and legacy unused spells become issues, never autogenerated placeholders.
- Verify `CreatureFamily.dbc` family ID, relevant skill-line relationship and actual eligible family. Family restrictions in old `Petopia` are a reference, not definitive 1.12 DBC provenance.
- Explicitly distinguish **spell present in 1.12 DBC** from **obtainable by tame** and **offered by trainer**. Spell existence alone is insufficient.
- Five **Rank 5 magic resistance** entries are currently suspected BC-era/unoffered in late Vanilla. Mark each `DISPUTED` until original 1.12 DBC **plus actual trainer offering** confirms its status. See [trainer report](COMPLETE-TRAINER-RANK-RESEARCH.md).

### Pet trainer spell wrapper: second required identity

Some Classic pet trainer pages display **a wrapper spell that teaches a pet skill**, e.g. [Nature Resistance trainer learn-spell 24512](https://www.wowhead.com/classic/spell=24512), distinct from [Nature Resistance pet aura 24492](https://www.wowhead.com/tbc/spell=24492). In-game trainer source/purchase eligibility needs a **separate** field `trainer_wrapper_id`, its own client rank/level and cost, and a reference to the resulting known rank. Do not put pet passive IDs into a trainer NPC's SQL table and assume correct behaviour.

## Phase C — prove *offered* source in Vanilla

- For wild ranks, use [tame source atlas](TAME-ABILITY-SOURCE-ATLAS.md), original beast creature entry and pet cast conditions.
- For trainer ranks, locate genuine late-original-Vanilla pet trainer inventory (NPC entries, trainer spell **wrapper IDs**, required Hunter level, price) in version-pinned source data. Check all seven Growl, ten Stamina, ten Armor and twenty *candidate* school resistance ranks.
- Separately record Rank 5 school resistance spells even when present in an emulator chain. **An early-BC spell in a 1.12-emulator archive is not proof it was trainer-offered in original Vanilla.**

## Phase D — compare against **the user's own installed** 3.3.5

We do **not** have the user's `acore_world.zip` or deployed DBC files available in the current project context. Repository source or the latest GitHub default branch cannot determine the **installed** realm's content.

Once an owner-approved read-only snapshot is supplied and **a backup exists**:

1. Pin exact AzerothCore/Core module/IP/Playerbots/Naxx Core commit, realm world DB revision, 3.3.5 client build and client patch/MPQ order.
2. Cross-check read-only copies of deployed **server** Spell.dbc/SkillLineAbility and **client** Spell.dbc; record independent checksums. A mismatched server/client pair must be flagged before diagnosing spells.
3. Build one row per **original** rank: `ability_key`, `rank`, original ID, source kind (wild/trainer), original min pet level/cost/effects, installed server ID and verified effects, installed client ID/tooltip/icon, family legality, native core pet rank/regrant behaviour.
4. Check native pet save/load path, WotLK default family spells, pet-talent auto-learning and individual-progression level catch-up. **Never** teach or remove production pet spells during this audit.
5. Confirm the actual local world DB schema before any `SELECT`. [Read-only SQL plan](READ-ONLY-SERVER-DATA-AUDIT.md) begins with `SHOW COLUMNS` and six candidate NPC entries; expand only after successful identifier check.
6. Distinguish the public **`spell_ranks.sql`** from server `Spell.dbc`: in the public upstream source, only **11 of 52** CMaNGOS trainer candidate IDs appear as exact entries in that SQL file (seven Growl, Nature Resistance 2–5). This **does not** establish spell data absence; it measures only that one optional/auxiliary SQL rank reference.

## Status codes for future machine-readable comparison

| Code | Meaning | Safe implementation behaviour |
|---|---|---|
| `ORIGINAL_DBC_VERIFIED` | Confirmed in exact original build, with hash/source | Research progresses; does **not** enable rank |
| `ORIGINAL_TRAINER_VERIFIED` | NPC offered correct wrapper in actual late Vanilla | Candidate for authentic trainer path |
| `ORIGINAL_WILD_VERIFIED` | Original tame NPC had particular natural teachable rank | Candidate learn-by-use source |
| `SOURCE_UNAVAILABLE` | Rank exists, but no verified tame source/trainer | Do not grant freely |
| `CROSS_ERA_CONFLICT` | Same ID/name has different 1.12 vs 3.3.5 effect | **Block** until safe resolution |
| `SERVER_335_VERIFIED` | Exact deployed server has matching spell effect | No presumption about client |
| `CLIENT_335_VERIFIED` | Exact deployed 3.3.5 client knows spell/tooltips | No presumption about native pet save |
| `PERSISTENCE_VERIFIED` | Module-only pet spell changes survive load/stable/restart | Necessary but still not full release |
| `OWNER_ACCEPTED` | Full QA including IP/bots/rollback signed off | May be considered in a release proposal |

## Out-of-scope during reference work

- Any `UPDATE`, `INSERT`, `DELETE`, `ALTER`, `REPLACE` or migration on **world/characters databases**.
- Editing or distributing `Spell.dbc`, MPQs or user game clients.
- Modifying AzerothCore, mod-individual-progression, Playerbots or Naxx Core source.
- Creating fake rank IDs or deciding a spell exists because `spell_ranks.sql` contains a same-named row.
- Assuming **all** documented Classic Era spell/trainer abilities were implemented exactly in original WoW 1.12 or can work unchanged in AzerothCore 3.3.5.

This is an actionable audit blueprint, not evidence the audit has already been performed.
